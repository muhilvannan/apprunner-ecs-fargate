# Milestone v0.1 Alpha

**Status:** ✅ SHIPPED 2026-03-30
**Phases:** 01–02 (Phases 03–04 absorbed into Phase 02)
**Total Plans:** 5 (01-01, 01-02, 02-01, 02-02, 02-03)

## Overview

First working release of ECS App Tester. Terraform provisions base AWS infrastructure (VPC, ECS cluster, ALB, IAM). A Python/FastAPI controller running in Docker manages workspaces as ECS services with multi-container tasks. App start/stop is implemented by toggling ALB listener rule actions. Live at `https://brewer.muhilvannan.com`.

### Phase 02: Controller API — Workspace & App Management

**Goal:** Build Docker API managing workspace lifecycle and app routing.
**Plans:** 3 plans (+ absorbed Phases 03 routing + 04 testing)

- [x] 02-01: Python/FastAPI scaffold, Docker, `/health` endpoint
- [x] 02-02: Workspace bootstrap — multi-container task def, ECS service, TGs, ALB rules
- [x] 02-03: App lifecycle (start/stop via ALB rule toggle), Streamlit baseUrlPath fix, live E2E test

**Key pivot:** Original plans specified Node.js/Express. Built with Python 3.12 + FastAPI + boto3.

**Details:**
- Multi-container task definition: all workspace apps in one task, one container per app
- Service named `{workspaceId}` at `desiredCount=1` — always running
- Start/stop = ALB `forward` ↔ `fixed-response 503` on listener rule (container never stops)
- Manual IP registration to TGs after task reaches RUNNING (no `loadBalancers` on service)
- Streamlit fix: `--server.baseUrlPath=/workspace{id}/{appId}` for static asset routing

## Milestone Summary

**Architectural Pivots:**

- Node.js → Python 3.12 / FastAPI / boto3 (simpler, canonical AWS SDK)
- Multiple tasks per service → 1 multi-container task per service (ECS console visibility requirement)
- CloudMap for routing → direct ALB IP registration + listener rule toggle
- Task lifecycle start/stop → ALB rule action modification (forward ↔ fixed-response 503)

**Key Decisions:**

| Decision | Rationale |
|----------|-----------|
| Python/FastAPI over Node.js | boto3 is canonical; fewer moving parts |
| Multi-container task | `run_task` tasks never appear under service; service scheduler required |
| ALB rule toggle for start/stop | Container stays warm; no cold-start on every start |
| No `loadBalancers` on service | ECS only supports 1 TG per service; N apps need N TGs → manual registration |
| `public.ecr.aws` images | No Docker Hub auth required on Fargate |
| Phases 03–04 absorbed | ALB routing fully implemented in Phase 02; no separate integration phase needed |

**Issues Resolved:**

- `ServiceNotActiveException` on DRAINING service → force-delete + recreate
- `TCP` health check protocol on ALB TG → changed to HTTP
- `ws-ws-` double prefix → service name = workspace ID directly
- Streamlit static assets 503 → `--server.baseUrlPath` flag
- `InvalidParameterException` on `run_task` group → removed group, switched to service scheduler

**Technical Debt:**

- No EFS mounting: containers do not mount EFS; `/app/sync` only lists S3 objects
- No formal test suite: verification was manual (live testing)
- Cold start ~90s: all app types install packages at runtime
- Streamlit uses `hello` demo app: user-supplied code not yet wired
- Phase 03 (CloudMap routing) and Phase 04 (test suite) were never formally executed
