## EFS Strategy

- Single EFS file system for entire cluster (cost-effective)
- Mounted at /mnt/efs by all tasks
- Directory structure: /mnt/efs/workspace{id}/app{id}
- Permissions scoped at OS level (chmod, task IAM role scoping)
- Access points optional (can add if access control needed per app)

## ALB Strategy

- Single ALB for cluster (reusable across all workspaces)
- HTTP listener on port 80 → redirect to HTTPS (optional)
- HTTPS listener on port 443 (certificate from ACM, user-provided)
- Target groups created per workspace (or dynamic by controller)
- Listener rules route by pattern: /workspace{id}/app-{id} → target group
</context>

<task type="auto">
  <name>Task 1: Create EFS File System with Mount Targets</name>
  <files>
    terraform/efs.tf
    terraform/outputs.tf (append)
  </files>
  <action>
Create **terraform/efs.tf** with EFS and mount infrastructure:

1. **EFS Security Group** (aws_security_group):
   - Name: efs-sg-${var.environment}
   - Ingress: NFS (2049) from ECS task security group (aws_security_group.ecs_tasks)
   - Egress: all (to allow return traffic)
   - This locks down EFS access to ECS tasks only

2. **EFS File System** (aws_efs_file_system):
   - Name: ecs-app-tester-efs-${var.environment}
   - Performance mode: generalPurpose (default)
   - Throughput mode: bursting (adjust if needed for high load)
   - Encryption: enabled (AWS-managed key)
   - Tags: { Name = local.cluster_name, Type = "shared-storage" }

3. **EFS Mount Targets** (aws_efs_mount_target — one per AZ):
   - For each private subnet from VPC (2 subnets recommended):
     - mount_target.subnet_id = private_subnet_id
     - mount_target.security_groups = [efs_security_group.id]
   - This ensures high availability (EFS accessible from any AZ)

4. **EFS Access Point** (aws_efs_access_point — optional but recommended):
   - Path: / (root, we'll manage subdirs at task level)
   - POSIX user: uid 1000, gid 1000 (non-root, safer)
   - Root directory: enforce_root_directory = true (optional, simplifies permissions)
   - This provides an additional isolation layer if needed later

5. **Update outputs.tf** — Append:
   - efs_id, efs_arn
   - efs_access_point_id (if using)
   - efs_dns_name (for mounting in tasks)
  </action>
  <verify>
terraform validate
terraform plan -var-file=terraform.tfvars 2>&1 | grep -E "aws_efs|aws_security_group" | head -10
  </verify>
  <done>
EFS file system created with mount targets in all AZs, security group restricts access to ECS tasks, access point configured
  </done>
</task>

    terraform/alb.tf

  <action>
Create **terraform/alb.tf** with ALB, target groups, and listener rules:

1. **ALB (Application Load Balancer)** (aws_lb):
   - Name: ecs-app-tester-alb-${var.environment}
   - Internal: false (expose to internet)
   - Load balancer type: application
   - Subnets: public subnets only (from VPC)
   - Security groups: alb_security_group (from VPC)
   - Enable deletion protection: false (allow destruction in dev)
   - Enable access logs: false (can enable if needed)
   - Tags: { Name = local.cluster_name, Type = "lb" }

2. **Target Group (Default/Generic)** (aws_lb_target_group):
   - Name: ecs-app-tester-tg-default-${var.environment}
   - Protocol: HTTP, Port: 80 (ALB talks to tasks on dynamic ports, we'll map later)
   - VPC ID: from VPC
   - Target type: ip (ECS will register tasks by IP)
   - Health check:
     - Protocol: HTTP
     - Path: /healthz (controller will provide this endpoint)
     - Interval: 30 seconds
     - Timeout: 5 seconds
     - Healthy threshold: 2
     - Unhealthy threshold: 3
     - Matcher: 200-299 (accept 2xx responses)

3. **HTTP Listener (Port 80)** (aws_lb_listener):
   - Port: 80
   - Protocol: HTTP
   - Default action: forward to target group OR redirect to HTTPS (user preference)
   - For now: forward to target group (HTTPS optional, can add later)

4. **HTTP to HTTPS Redirect (Optional)** 
   - If user provides ACM certificate ARN via variable:
     - Add HTTPS listener (port 443, certificate_arn = var.ssl_certificate_arn)
     - Update HTTP listener to redirect (301) to https://${domain_name}

5. **Update outputs.tf** — Append:
   - alb_id, alb_arn, alb_dns_name
   - target_group_arn (default)
   - alb_listener_arn (for later rule updates in Phase 03)
   - alb_listener_https_arn (if HTTPS enabled)

**Note:** Dynamic listener rules per workspace will be created by controller API (Phase 02) or handled in Phase 03 Integration. For now, ALB is ready to receive traffic.
