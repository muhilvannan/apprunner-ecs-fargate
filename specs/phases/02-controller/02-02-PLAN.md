<objective>
Implement workspace bootstrap functionality in the controller API. 

Purpose: Enable the API to create ECS services for workspaces on demand and set up scoped S3 access in IAM.

Output: `/api/workspace` POST route with workspaceId input and service generation.
</objective>

<tasks>
<task type="auto">
  <name>Implement workspace bootstrap endpoint</name>
  <files>
    controller/src/routes/workspace.ts
    controller/src/types/workspace.ts
  </files>
  <action>
Create POST /api/workspace endpoint expecting body:
  { workspaceId: string, s3Bucket: string, apps: [{appId, image, port}] }
- Validate inputs.
- Call IAM service: create workspace task role if missing, attach inline S3 read policy for requested bucket.
- Call ECS service: register Fargate task definition with EFS volume mount /mnt/efs/workspace{workspaceId}/app{appId}, CloudMap service identifier.
- Call ECS service: create ECS service with desired count=0 (apps started on-demand), associate with ALB target group placeholder.
- Call CloudMap service: create namespaced service record.
- Respond with created workspace metadata and ARNs.

Use try/catch and return 4xx/5xx.
  </action>
  <verify>
Start server and execute: 
curl -X POST http://localhost:3000/api/workspace -H 'Content-Type: application/json' -d '{"workspaceId":"ws1","s3Bucket":"mybucket","apps":[{"appId":"app1","image":"nginx","port":80}]}'

Expect 201 and JSON with workspaceServiceArn, cloudMapServiceId.
  </verify>
  <done>
Workspace endpoint creates ECS components in AWS (or mocks in dry run) and returns expected 201 response.
</done>
</task>
